Well, could be either or neither! But first, what are KVMs over IP?

Keyboard, Video, and Mouse over Internet Protocol (KVM over IP) are devices that plug into a computer via the USB and HDMI/DVI ports and give you full, out-of-band control of a computer as if you were physically at the keyboard, mouse, and monitor. Often times, these devices have built in web GUIs. Additionally, these devices provide control at the hardware level, meaning they operate independently of the OS. What this means is that a user can access anything on the host remotely without leaving artifacts in the OS.

In case this isn't painting a picture for you, this is a great way for employees to work multiple jobs with their company-provided devices without leaving evidence of it (besides the logs showing that the KVM over IP is connected to the computer). Its also a great way for threat actors to exfiltrate data from a host device over the internet without leaving a breadcrumb trail. In fact, the Democratic People's Republic of Korea (DPRK A.K.A. North Korea) has been using these devices to exfiltrate data from U.S. employees who voluntarily agree to connect these devices to their company computers.Additionally, the DPRK uses these devices to operate their computer farms. These farms are used by the DPRK to be "employed" (illegitimately) to receive income from U.S. companies. In turn, they use this money to fund their illicit weapons programs.

That said, there is a possibility for someone in your organization is using a device like this for whatever reason. For many organizations, this can be a policy violation that you can hunt for and build the detection for. Generally, the KVM over IP devices seen in use are the PiKVMs and Tiny Pilot KVMs. These are consumer-grade devices that anyone can acquire for less than $200. Below is a Kusto Query Language (KQL) query that you can use to identify these devices (I intend to provide Sigma rules for all query's I post, including this one in the future). Below the query, I break it down:

```
DeviceEvents 
| where ActionType in ("USBDeviceConnected", "UsbDriveMounted", "UsbDriveUnmounted", "UsbDeviceDisconnected", "DeviceDisplayConnected", "PnpDeviceConnected") 
| extend Fields = parse_json(AdditionalFields) 
| extend Manufacturer = tostring(Fields.Manufacturer), ProductName = tostring(Fields.ProductName) 
| extend SerialNumber = tostring(Fields.SerialNumber), ProductName = tostring(Fields.ProductName) 
| extend vendorid = tostring(Fields.DeviceId) 
| where Manufacturer has_any ("PiKVM","tinypilot") or vendorid contains "6b65796d696d6570690" or SerialNumber == "CAFEBABE" 
| project TimeGenerated, Manufacturer, SerialNumber, ProductName, ActionType, DeviceName, InitiatingProcessAccountUpn, InitiatingProcessCommandLine, vendorid
```

Here, we are looking at the "DeviceEvents" table as this provides us with the raw event stream for device activity collected by Defender for Endpoint. Next, we look at the "ActionType" field which looks for any of the provided terms seen in that field:

```
| where ActionType in ("USBDeviceConnected", "UsbDriveMounted", "UsbDriveUnmounted", "UsbDeviceDisconnected", "DeviceDisplayConnected", "PnpDeviceConnected")
```

Next, we use the "extend" operator 4 times to parse addition fields using JSON to enable us to look for certain keys in those fields. Those keys are then extended with the next 3 extend operators, enabling us to find the key terms we specify later in the query:

```
| extend Fields = parse_json(AdditionalFields) 
| extend Manufacturer = tostring(Fields.Manufacturer), ProductName = tostring(Fields.ProductName) 
| extend SerialNumber = tostring(Fields.SerialNumber), ProductName = tostring(Fields.ProductName) 
| extend vendorid = tostring(Fields.DeviceId)
```

Finally, we look at the specific values of the manufacturer, vendor ID, and serial number to identify the values that correlate with the PiKVM and Tiny Pilot devices. The reason we are searching for the specific vendor ID "6b65796d696d6570690" and serial value "CAFEBABE" is because this is the default information that is used for these devices and not unique to each specific device. From here, we finish off using the "project" operator to only show us what fields are valuable to us:

```
| where Manufacturer has_any ("PiKVM","tinypilot") or vendorid contains "6b65796d696d6570690" or SerialNumber == "CAFEBABE" 
| project TimeGenerated, Manufacturer, SerialNumber, ProductName, ActionType, DeviceName, InitiatingProcessAccountUpn, InitiatingProcessCommandLine, vendorid
```

If you get results, don't panic! Before you start notifying your leadership, legal, and HR teams, remember, the only thing we can see is the device actually being used. We cannot see the devices connecting to the KVM, what they were doing, etc.

Additionally, if you are thinking about pulling in the company-provided computer, know that the forensics investigation will show just as much as the logs do. The only way to actually know what was happening on the KVM is to pull that in for forensics. And since, chances are, these are not company-provided, it will be a challenge to legally pull a personal device like this for forensics. However, it would be worth looking at if these devices are externally facing as this poses a major risk. If someone is able to obtain credentials, they can access anything from the device remotely without leaving artifacts on the host.

So, if your organization prohibits these devices in their policy, this is a way for hunt for some of the most prolific ones. And if your organization does not have a policy in place to prohibit the use of these devices, it is absolutely worth bringing up to the appropriate team.

Happy hunting!
